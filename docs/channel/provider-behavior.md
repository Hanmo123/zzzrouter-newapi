# 服务商、渠道评测与价格行为约定

本文记录服务商、渠道、评测与价格的已生效行为。渠道模型 Token 单价覆盖用于用户计费基础价；采购成本、成本路由与 ClickHouse 镜像是独立边界。

详细 API、迁移与实现说明见 [PROVIDERS.md](../../PROVIDERS.md)。

## 1. 实现状态

| 能力 | 状态 | 行为 |
| --- | --- | --- |
| 服务商与渠道关联 | 已实现 | 一个服务商可包含多个渠道，凭据和协议配置仍属于渠道 |
| 渠道上游倍率 `upstream_ratio` | 已实现 | 用于 `floor` 排序与 `multiplier` 筛选，不直接参与用户扣费 |
| 渠道公开倍率 `public_ratio` | 已实现 | 用于公开展示和实际用户计费，与上游倍率独立 |
| 系统模型价格 | 已实现 | 沿用系统模型计费配置，可包含 token 计费、固定价或计费表达式；不是自动实时同步的官方报价 |
| 渠道 × 模型独立 Token 单价 | 已实现 | 在渠道编辑中按对外模型设置输入、输出、缓存及图像/音频 Token 的用户计费基础价；优先于系统价 |
| 逐次渠道评测历史 | 已实现 | 主库追加保存真实结果，独立于可清理的系统任务及消费日志 |
| 公开服务商历史页面 | 已实现 | 展示 TTFT、按检测样本计算的可调用情况和最近记录 |
| 平台数据与每日 Token 用量 | 已实现 | 首页及 `/usage` 自动读取公开目录/评测统计，Token 总数来自实际消费日志；不使用手工数据，不按模型拆分、不含 UTC 当天 |
| ClickHouse 评测写入 | **尚未实现** | 已隔离存储契约，未来通过事务 outbox 异步镜像，不在主库事务内远程双写 |

## 2. 三类价格概念不能混用

### 系统模型计费配置

未配置渠道模型 Token 单价时，这是用户费用计算的模型基础。输入、输出、缓存等用量按照现有模型配置计算；表达式和固定价遵循各自的既有计费方式。配置渠道覆盖后，匹配的 Token relay 请求改用该渠道的独立单价，不改写系统价。

“回退系统模型价”不等于“实时读取官方价格”：管理员可能已修改系统价，内置参考价格也不承诺自动跟随厂商变动。

### 上游采购价格与倍率

上游采购价表示服务商收取运营方的成本。当前只保存渠道级 `upstream_ratio`，**没有保存逐渠道、逐模型的倍率前采购基础价**。

倍率是无量纲数，不能单独表达美元单价、币种、输入/输出差价、缓存优惠或阶梯价格。只有基准价和单位对齐时，不同渠道的倍率才可以直接作为成本比较依据。

### 用户计费基础价与公开倍率

用户计费基础价是用于向用户收取费用的模型价格；它不必等于采购价。`public_ratio` 是渠道对这一费用的公开倍率，不是模型单价。

两个渠道级倍率目前均默认 `1`，要求有限且大于零。修改上游倍率不应隐式修改用户价，修改公开倍率也不应隐式修改采购成本或 `floor` 排序。

## 3. 当前实际扣费与重试行为

普通模型费用的组合关系为：

```text
用户费用 = 按实际渠道模型单价计算的费用（未覆盖时按系统模型配置）
         × 生效分组倍率
         × 实际渠道 public_ratio
         × (1 + 生效服务费率)
```

- 用户专属分组倍率按原有优先级替代普通分组倍率，不将两者重复相乘。
- 服务费是最终费用中的组成部分，不是在最终扣费之外再收一遍。关闭服务费时费率按零处理。
- 工具附加费用沿用现有的倍率规则；违规罚金遵循原有独立规则，不套用上式追加服务费。
- 请求冻结服务费设置。重试换到另一个渠道时，按实际渠道更新公开倍率和预扣；需要更多预留时先补足，实际结算更便宜时返还差额，请求失败时按原有流程退款。
- 异步任务保留其计费快照；后续配置变化不能重算已经结算的历史费用。
- `upstream_ratio` 不在上述用户扣费公式中，采购成本也不会通过匿名目录或用户消费日志公开。

例如，假设一次按系统模型配置算出的费用为 1 美元、分组倍率为 2、渠道公开倍率为 1.2、服务费率为 5%，则组合费用为 2.52 美元。此例仅说明乘法关系，不代表任何模型的真实报价；实际 quota 换算与舍入仍由系统执行。

实现入口：`relay/helper/price.go`，以及 [最终计价说明](../../PROVIDERS.md#冒号路由与最终计价)。

## 4. 当前 `floor` 并不比较逐模型绝对采购价

当前 `floor` 按 `upstream_ratio` 从低到高选择渠道，同倍率档内沿用渠道权重，耗尽后再进入更高倍率档。`multiplier` 条件同样比较这个上游倍率，不比较公开倍率或用户费用。

以下为假设的单一输入用量示例，单位为美元/百万输入 token：

| 渠道 | 服务商倍率前输入价 | 上游倍率 | 折后采购价 |
| --- | ---: | ---: | ---: |
| A | 10 | 0.8 | 8 |
| B | 5 | 1.0 | 5 |

当前 `floor` 会优先 A，因为 `0.8 < 1.0`，但示例中的实际输入采购价是 B 更低。这正是“服务商倍率前价格不对齐”时，单一渠道倍率不足以表达成本的原因。**当前代码不会读取表中的倍率前价格，它们只是解释需求的假设值。**

同时，最低输入价不必然等于最低总成本：输出、缓存、按次收费和阶梯价格也可能不同。未来若要按真实采购成本路由，需明确比较口径，不能未经确认直接把 `floor` 改成按某一个单价排序。

## 5. 渠道评测与公开历史

- 定时任务和全量 `degradation-check` 扫描使用渠道凭据发起真实请求，可能产生上游费用；不进入本地用户 relay 扣费流程。打开服务商详情页面只是读取历史，**不会触发新评测或收费请求**。
- 已开始的评测返回正常、疑似降智、请求失败或取消结果后，按 UUID 独立追加；重复 UUID 不覆盖事实。取消或丢失任务租约时，仍尝试以每条最多 5 秒的独立写入上下文保存已返回结果，但不更新渠道快照、路由或任务进度。数据库写入失败会使任务失败，不承诺进程崩溃时能保存尚在内存中的结果。
- 未派发目标、被资格规则跳过的目标及 dry-run 不制造历史。独立 `degradation-probe --endpoint ...` 是不绑定渠道的无数据库诊断工具，不伪造服务商归属。
- 单模型定时检测在正常条件下将事实与快照同事务提交；全量扫描先存逐模型事实，仅在完整、未中断且租约/配置校验通过时发布渠道汇总。模型级事实不应被混称为渠道整体健康快照。
- `normal` 与 `abnormal` 都表示可调用，后者另外计为疑似降智。取消或无效目标/协议/代理/请求配置在公开统计中归为 `unknown`，不视为上游离线。

```text
检测可调用率 = online / (total - unknown)
```

没有可判定样本时不显示百分比；它是样本次数统计，不是连续在线时长或 SLA。

- 服务商详情支持近 7/30/90 天的 UTC 每日统计、每日 TTFT 曲线和范围内最新 50 条记录。TTFT 均值只使用可调用且实际测得首 token 的样本，按样本数计算全范围加权均值；0ms 是有效值，缺测不插值，也不使用总耗时替代 TTFT。
- 评测开始/完成、历史范围和每日桶使用 Unix **毫秒**；目录快照的 `last_checked_at` 使用 Unix **秒**。
- 历史不套用目录默认的最新在线/未降智筛选来隐藏过去的失败。公开可见性仍由主库的当前渠道状态、服务商状态和实例身份决定；复制、删除后重建及调整服务商归属不转移原身份的历史。
- 停用或删除不级联清理事实；历史当前没有默认过期清理任务。但未公开的渠道/服务商记录不能通过匿名接口读取。
- 公开响应不含 Key、Endpoint、原始回答/错误、映射后上游模型、上游采购成本或内部任务配置。检测开关与渠道路由启停相互独立。

参数、返回字段与统计口径见 [历史 API 说明](../../PROVIDERS.md#匿名历史查询与统计口径)。

## 6. ClickHouse 扩展边界

当前 `EvaluationHistoryStore` 将追加事实与时间范围读取同页面逻辑、主库授权查询解耦。当前运行环境以 PostgreSQL 为事实来源；关系库适配器仍兼容 SQLite/MySQL。

未来启用镜像时的计划链路是：

```text
主库事务：样本事实 + outbox（正常情况下还包括快照更新）
    → 提交
    → 后台认领待投递事件
    → 批量写入 ClickHouse
    → 确认投递；失败重试
```

- 此 outbox 和 ClickHouse 写入器**当前没有实现**，不应把修改 `SQL_DSN` 或消费日志库配置当作启用评测镜像的方法。
- 至少一次投递以样本 UUID 去重；晚到事实不能仅按评测开始时间或最大序号水位被跳过。
- `ReplacingMergeTree` 的最终合并不是即时唯一约束；查询和统计层必须避免重投事件重复计数，不能直接对未去重输入累加可调用率或均值。
- 读适配器切换前验证数据回填、同步积压和水位，不能把镜像延迟当成真实缺测或故障。
- 渠道/权限及未来价格配置仍由主库负责，不通过分析库的历史查询替代交易与授权边界。

完整扩展约定见 [ClickHouse 设计](../../PROVIDERS.md#后续-clickhouse异步镜像而非事务内双写)。

## 7. 渠道 × 模型独立 Token 单价

### 配置与覆盖口径

内置控制台「渠道 → 编辑 → 渠道模型 Token 单价」选择一个对外模型并开启覆盖。一个服务商的多个渠道、同一渠道的多个模型均各自保存价格，单位统一为 **USD / 百万 Token**，不是相对官方价的倍率。

价格保存在既有 `channels.settings` JSON 的 `model_token_prices` 中，沿用渠道创建/更新 API，不增加表或列。示例（此处只是示范，不代表真实报价）：

```json
{
  "model_token_prices": {
    "public-model": {"p": 2, "c": 8, "cr": 9, "cc": 3.75, "cc1h": 7}
  }
}
```

| 字段 | 单价对象 |
| --- | --- |
| `p` / `c` | 输入 / 输出 Token（必填） |
| `cr` | 缓存读取 Token |
| `cc` / `cc1h` | 缓存写入（5 分钟 / 通用） / 1 小时缓存写入 Token |
| `img` / `img_o` / `img_cr` | 图像输入 / 图像输出 / 图像缓存读取 Token |
| `ai` / `ao` | 音频输入 / 音频输出 Token |

- 一条覆盖记录替代该请求的完整系统基础定价。必填输入/输出；可选类别留空时仍属于输入/输出，按对应基础单价计费，**不继承系统的缓存倍率或阶梯价**。例如 `cr: 9` 可以高于 `p: 2`；缓存写入两种时长也无需固定比例。
- 显式 `0` 是免费单价；负数、null 类别、未知类别、非有限数、超过 10 亿美元/百万 Token 的价格均拒绝。关闭覆盖（移除该模型记录）后完整回退系统模型配置；空 map 表示无覆盖。
- 优先匹配请求的对外模型名称；带请求修饰符时再回退对外基础名。不会用映射后的上游模型 ID 或全局计费别名替换渠道匹配身份。未声明的旧模型记录可以保留/移除，不会单独让该模型变得可路由。
- 覆盖用于同步 HTTP/SSE、Responses WebSocket 及 Realtime 的 Token relay。任务插件仍按其已有 `u()` 用量表达式结算，按次/张/秒等任务价格不受此配置影响。没有 Token 用量明细时仍受原有上游用量与估算能力限制，不虚构缓存或模态数量。
- 这是**用户计费基础价**，不是私有采购账本。仍乘实际分组倍率、渠道 `public_ratio` 与被冻结的服务费设置；不乘 `upstream_ratio`，不修改 `floor`/`multiplier` 的采购倍率语义。

### 快照、权限与兼容

- 保存权限沿用 `settings` 的 `channel.sensitive.write`；无此权限时控制台价格字段只读，原有服务端权限检查仍有效。价格配置不加入匿名目录的 settings 投影，也不公开凭据或采购成本。
- 每次采用覆盖时生成自包含计费表达式，并进入原有请求计费快照。配置修改不重算执行中的同一渠道请求；重试更换渠道时重新选择价格（包括移除上一个渠道的覆盖），发送前补足更高预扣，最终结算/失败退款仍由原有会话处理。
- 消费日志保存实际采用的表达式（`expr_b64`）和倍率，`matched_tier: channel` 标识渠道覆盖。旧日志、系统定价与既有任务快照不迁移或重写。
- 模型列表会识别当前可用分组渠道上的独立定价，不要求同一模型同时有全局价格。模型映射、协议设置或自动模型发现更新不会删除已保存的渠道单价。
- 持久化与目录查询回归实际运行于 SQLite 3.50.4、MySQL 8.0.46、PostgreSQL 16.15；覆盖既有无覆盖记录的升级、重复启动式 AutoMigrate、保存/清除/设置更新保留、分组与启用范围。未验证更低数据库版本，也未新增数据库专属语法或迁移。

## 8. 平台数据与自动每日 Token 统计

### 公开平台概览

- `GET /api/public/platform` 匿名只读，不接受 query 参数；仅返回 `as_of`、`providers`、`channels`、`models`、`evaluations_24h` 和可为空的 `latest`。
- 数量基于当前公开、启用且服务商可见的渠道，不使用默认「在线/未降智」过滤隐藏其它公开状态。模型数为真实声明模型去重数，不将固定默认筛选模型冒充已配置模型。
- 评测数量及最近记录来自追加式事实，并关联当前渠道实例和服务商；停用/私有、复制后的旧实例、已调整归属及未来时间样本不进入当前统计。最近记录只投影公开状态、Unix 毫秒开始时间和可为空的实际 TTFT；0ms 保留，取消/配置错误归为 unknown，不输出凭据、私有错误或原始响应。
- 首页移除演示服务商/模型数量、请求次数、假响应、虚构 TTFT 与倍率。保留原宣传文案、绿色荧光笔与彩色代码，两张装饰性浮动卡片及请求明确标注为示例，不把示例路由/探测当作实际观测；默认模型为 `gpt-6.1-sol`；主机/接入示例取浏览器当前 location，不改变可信服务端 Origin 配置。固定默认筛选不修改渠道、不创造真实目录中不存在的可调用资源。旧首页模型手动配置不再影响公开元数据，管理页面不提供该覆盖表单。

### Token 来源与发布口径

- `/usage` 以「平台数据」展示平台概览，以及单条全站每日 Token 总数的 Unovis 柱状图；不是调用次数，不按模型细分。保留粉色、浅色背景、无网格轴、7/30/90/365 天范围（默认 30 天），Token 总量/日均/峰值三项；供应商 TTFT 图不变，页脚不含推广横幅。
- `GET /api/public/usage/daily?days=30` 从配置的 **LOG_DB** 而非固定主库读取 `LogTypeConsume`，按 UTC 日累加已记录的 `prompt_tokens + completion_tokens`。不由 quota、价格、请求次数或手工数值推算 Token；不计错误/退款等其它日志，不计非法负数。即使主库和日志库分离，也必须读真实日志来源。
- 公开范围仍截至 UTC 昨天，只含完整历史日期。今天和未来日志不会提前显示；无日志日为 null，不能用虚构零值补齐。日志禁用/清理造成的缺口不代表无消费；本统计表示现存消费日志中记录的 Token，不承诺清理后的历史完整性。
- 返回 `success/message/data`，data 含 `unit: "tokens"`、`source: "consumption_logs"`、`timezone: "UTC"`、`from/to`、`days/total/recorded_days` 和连续日期数组 `{date, token_count}`。仅允许 `days=7|30|90|365`，拒绝空、重复、未知参数和 `to`。API 不返回用户名、日志详情、请求 ID、quota、编辑者或私有上游字段。
- 单日及范围总量必须是 JavaScript 安全非负整数，不再受旧手工输入的 1T 限制；超过安全边界返回通用失败而不是舍入或截断。SQL 聚合兼容 SQLite/MySQL/PostgreSQL，MySQL 使用 SIGNED 转换避免默认整数除法/类型差异；日志库 ClickHouse 分桶沿用其 intDiv 方言，未把消费日志存储配置当成评测 ClickHouse 镜像。
- K/M/B/T 显示最多一位小数，原整数不变。日志真实零值保留 1px 标记；null 日期在图形、坐标、悬停与键盘中完全跳过。日均仅按有记录日期计算，不插值或补零。
- 前端禁用读取缓存，焦点/可见状态恢复与可见期间每 30 秒刷新；错误可重试，不回退演示数据。键盘聚焦使用即时滚动，避免全局平滑滚动时 Unovis 将尚在图外的 tooltip 隐藏。

### 停用手工设置与数据兼容

- 管理「系统设置 → 前端配置」仅展示自动统计说明，暂不提供手工首页模型或每日 Token 编辑。
- 生产路由不再注册旧 `/api/option/daily_usage` GET/PUT/DELETE；相关遗留模型/控制器/编辑器代码与迁移保留以兼容旧存储，但不能当作当前可使用的管理入口。
- `public_daily_usages` 及其旧 `request_count` 物理列原样保留，不删除历史手工值，也不将其转成消费日志。旧值、未来手工值及旧首页配置均不影响公开统计；没有消费日志就展示无数据，不把旧手工值当成真实消费。
- 本变更只读取既有消费事实，不写消费日志、不调整额度、价格、账单或退款流程。

### 验证边界

- 真正的 SQLite/MySQL/PostgreSQL 回归覆盖当前公共作用域/旧实例/未来评测、独立日志来源、零/缺测、超过旧 1T 输入上限的真实汇总、日期范围及私有字段隔离。
- 浏览器契约测试覆盖默认模型、手动首页元数据被忽略、实际平台字段/错误重试、当前浏览器域名、导航、Token 悬停/键盘/刷新及 365 日窄屏。管理组件验证只读且不查询或提交旧手工 API；旧存储回归继续验证数据保留。
- 测试矩阵使用隔离库，不对运行中的应用库进行清表测试；最低数据库版本、ClickHouse 运行联调和生产备份演练未在本次验证范围内。
