# 服务商、渠道评测与价格行为约定

当前价格、上游折扣和观测属于 **渠道 × 对外模型**。管理接口、字段、权限与 CLI 说明见 [PROVIDERS.md](../../PROVIDERS.md)。

## 1. 实现状态

| 能力 | 当前行为 |
| --- | --- |
| Provider / Channel | Provider 表示实际上游服务商；渠道保留协议、地址、凭据、模型映射与路由启停 |
| 模型独立计费 | `model_configs[公开模型名]` 保存手工公开倍率或原生 Token 表达式，以及上游折扣 |
| New API 价格导入 | 手动读取指定分组公开目录，完整比较后优先倍率，否则保留阶梯/表达式；保存渠道草稿生效，记录来源供后续任务复用 |
| Sub2API 价格导入 | 手动读取公开 `/api/v1/model-plaza`，按分组名称或 ID 获取单价和分组倍率；支持 Token 阶梯，分时和按次价格逐模型拒绝导入 |
| 自动公开倍率 | 提取表达式基础档 Token 价格，除以当前系统配置价，展示单值或最小～最大区间 |
| 调度 | 无法比较的表达式不参与调度；floor 先按公开倍率上限、再按下限排序 |
| 采购成本 | 基础费用乘上游折扣，独立于服务费和分组倍率；只在管理日志公开 |
| 模型观测 | 在线、降智、TTFT、检测时间按模型维护；历史逐次追加 |
| 平台数据 | 来自真实渠道/评测；每日 Token 来自 LOG_DB 消费日志 |
| ClickHouse 评测镜像 | 尚未实现；已有存储契约，未来用主库事务 outbox 异步投递 |

## 2. 系统价、模型计费基础与采购成本

系统配置价仍保留，管理员可能改过，并非自动跟随官方实时价格。它既是无渠道模型表达式时的基础价，也是表达式公开倍率的比较分母。有效表达式缺少可比较系统价时仍可保存，但该模型不能调度。

```text
S(u) = 系统模型基础费用，不含公开倍率、服务费、分组倍率
B(u) = 有模型表达式时 E(u)；否则 S(u) × 手工公开倍率
用户费用 = B(u) × (1 + 服务费率) × 生效分组倍率
采购成本 = B(u) × 上游折扣
```

上游折扣默认1，范围0..1；手工公开倍率默认1，允许零。表达式与显式手工倍率互斥，自动倍率不能再次乘入表达式费用。用户专属组倍率替代普通组倍率，最后应用一次。分组倍率为零时用户免费，采购成本仍按独立用量记录。最终边界换算/舍入，不从舍入后的用户金额反推成本。

例如基础费用1美元、折扣0.8、服务费5%、组倍率2：用户扣2.1美元、采购成本0.8美元。

## 3. 表达式与报价

复用 [newapi 原生表达式](../../pkg/billingexpr/expr.md)，实际结算执行完整表达式，包括上下文阶梯。报价仅提取默认服务等级、`len=0` 基础档，分别比较输入、输出、缓存及图像/音频类别当前系统价。全部比例相同显示 `0.1x`，不同显示 `0.1x～0.15x`。

服务等级支持 `param("service_tier") == "档位"` 及其 AND/OR 条件。公开列表使用未指定服务等级的报价；HTTP 请求、WebSocket 每次调用在选路前冻结原始 `service_tier`，在缓存/数据库、指定渠道、会话复用和重试路径按对应档位比较渠道与系统参考价。`floor` 和 `multiplier` 均使用该请求档位的区间，实际结算仍执行全部上下文阶梯与请求规则，不重复乘报价倍率。

按次、非线性、其他请求条件、时间条件、混合单位或不可提取的表达式返回 null，不参与对应请求调度。正价类别没有有效系统分母时不能通过忽略该类别伪造可比较报价。系统价修改直接影响后续比较，不重写渠道表达式或历史账单。

结构化导入价格按每个上下文档位补齐 `cc1h → cc → p`：仅字段缺失时继承，显式零价不回退，null/非法值报错。继承结果明确写入生成的表达式，不在报价阶段临时猜测。`gpt-6-astra` 内置参考表达式明确设置 `cc1h` 为基础档12.5、长上下文档25（USD/百万 Token），与 `cc` 相同；这是本地缺省继承约定，不是新增官方TTL报价。已有手写表达式及管理员覆盖价不自动改写。

可选变量完全遵循原生归一化规则；Anthropic 缓存写入不自动并入 `p`，需显式设置 `cc`、`cc1h`。任务插件的 `u("seconds")` 使用任务用量单位，渠道 Token 表达式不能套用到任务结算；任务继续使用系统任务表达式与模型手工倍率/折扣。

## 4. floor 与 multiplier

`floor` 使用公开倍率区间的上限升序，上限相同时下限升序；端点都相同才沿用权重。上游折扣不参与这一排序。

```text
0.14x < 0.13x～0.15x < 0.15x < 0.16x < 0.17x
```

`multiplier` 要求整个区间满足条件，例如 `0.1x～0.15x` 不满足 `<=0.12`。多个条件AND。无法比较的模型在普通、floor、指定渠道和重试候选中都被排除。模型 ACL、分组、路径/插件能力仍有效，不能用路由后缀扩大权限。

重试排除已尝试渠道，更换渠道时重建表达式、倍率和折扣快照，补足更高预扣才发送请求；最终结算成功尝试，失败返还预留。服务费在请求开始时冻结。执行中的同一渠道请求和异步任务不因后续配置修改而重定价。

日志中的服务费是实际总扣费的组成部分，不额外扣一次。`admin_info.upstream_discount/upstream_cost_quota` 保存独立成本；异步重算记录差额和总成本，任务保留快照。无法提供独立用量基础的旧适配器只返回最终用户金额时，不伪造采购成本。用户日志和公开目录不返回这些私有字段。

## 5. 模型观测与公开历史

在线、降智、TTFT与检测时间都按渠道模型维护，null表示未知，false与0是已知值。渠道启停仍是连接/路由控制，不以未知观测冒充可用。原 response_time/test_time 不当作 TTFT。

CLI全量扫描、局部模型扫描和定时任务只更新实际被测模型；不生成渠道汇总或把某个模型结果复制给所有模型。已修改的配置、手工观测、新实例、过期租约不会被旧请求覆盖。失败保留该模型最近成功延迟。

历史通过UUID追加，稳定实例身份隔离复制/删除重建，调整服务商归属不转移历史。取消或失去租约仍尝试保存已返回真实事实，但不更新快照；未派发、跳过及dry-run不制造事实。模型检测默认关闭，Provider/渠道排除开关优先，查看历史不触发收费请求。

`normal/abnormal` 都可调用，后者标记疑似降智；取消/无效配置归 unknown。可调用率为 `online/(total-unknown)`，无分母不显示百分比；这是样本统计，不是持续在线时长或SLA。TTFT均值只取可调用且实际测得的样本，按样本数加权，缺测不插值。

历史使用Unix毫秒，目录 last_checked_at 使用秒。匿名历史遵守当前渠道/服务商公开资格与实例身份，不用当前健康状态过滤掉历史失败，不返回原始响应、凭据或映射后上游模型。

## 6. ClickHouse 扩展边界

当前事实在主关系库，兼容SQLite/MySQL/PostgreSQL；`EvaluationHistoryStore` 隔离追加与读取。ClickHouse outbox和写入器尚未实现，不能通过更换LOG_DB启用评测镜像。

未来链路为主库事务写事实+outbox，提交后批量异步投递并确认。至少一次投递以UUID去重，不能把ReplacingMergeTree的后台合并当即时唯一约束；查询必须避免重复计数，晚到记录不能只按时间水位跳过。读取切换前核对回填/积压，不能把镜像延迟当真实缺测。

## 7. 配置管理与测试环境

控制台提供可搜索模型表格和展开式编辑，复用原生表达式编辑器。API `model_configs` 整体替换、省略保留、空对象清空；传 `model_configs_revision` 可防止旧草稿覆盖新配置或探测结果。模型配置需要 `channel.write`；凭据仍受敏感权限保护。复制继承价格、清空所有模型观测。

新列由正常启动AutoMigrate建立，本次未操作任何运行服务。原渠道级字段和 `settings.model_token_prices` 已停止被新计价/调度/目录读取；测试环境按新模型配置重新设置，不做历史价格兼容换算或观测回填。旧物理列未主动删除。

公开列表一行对应一个渠道模型，`model` 为单个名称，`public_ratio` 为 `{min,max}` 或null。先展开再过滤/排序/分页；服务商数量按渠道去重。默认只列明确在线且未降智的模型，all/unknown可查看其他观测状态，仍不能绕过渠道停用或服务商删除。

## 8. 平台数据与自动每日 Token 统计

- `GET /api/public/platform` 不接受查询参数，返回 `as_of/providers/channels/models/evaluations_24h/latest`。渠道数量与声明模型数来自启用且服务商公开的真实渠道，不把默认筛选模型当真实资源；评测限定当前实例/归属及时间，最新TTFT允许null和零。
- 默认公开模型仍为 `gpt-6.1-sol`；首页模型选项来自真实目录，不使用旧手工首页配置。装饰示例不是统计事实，连接示例使用浏览器当前域名，不修改认证可信Origin。
- `GET /api/public/usage/daily?days=7|30|90|365` 从LOG_DB实际 `LogTypeConsume` 汇总输入+输出Token，按UTC截至昨天的完整历史日统计。错误/退款、负数、当天/未来值不计，不从金额或调用次数估计Token。
- 缺失日null，真实零有效；日志禁用/清理造成的缺口不代表零消费。返回 `unit:tokens/source:consumption_logs/timezone:UTC/from/to/days/total/recorded_days/items`，每日项为 `{date,token_count}`。超过JavaScript安全整数范围则返回错误，禁止舍入截断；不公开日志身份或详情。
- `/usage` 为单条全站Token柱图，7/30/90/365天、默认30天，显示总量/有效日期均值/峰值；K/M/B/T仅格式化显示。零值保留最小标记，null不补点。焦点/可见状态恢复及可见期间30秒刷新，错误可重试，不回退演示数据。
- 管理前端配置只展示自动统计说明，旧 `/api/option/daily_usage` 写入路由停用。旧表及手工值保留但不参与统计，不转成消费日志，也不重算账单。

本次验证使用本地文件/内存数据库及测试进程，不启动、停止或重启应用/数据库服务。未配置现有MySQL/PostgreSQL测试实例时，相应矩阵项跳过；不能把以前版本的数据库或浏览器验证结果算作本次验证。
